# Questionnaire

## Definition

A **[questionnaire](https://build.fhir.org/questionnaire.html)** in Care is the definition of a structured form: its title, its questions, and the order of those questions.

A questionnaire is a template, not a submission. When staff fill in a questionnaire, Care saves the answers as a [Questionnaire Response](../clinical/questionnaire-response.mdx), and the response records the version of the questionnaire that was used.

You manage the questionnaires of your facility in **Settings**, in the **Forms** group, under **Questionnaires**.

## Key Attributes

| Components | What it captures |
| --- | --- |
| Title | The name of the questionnaire. This field is required. |
| Slug | A short name that identifies the questionnaire in the facility. This field is required. |
| Description | A short text that explains the purpose of the questionnaire. This field is optional. |
| Status | Active, Draft, or Retired. Staff can fill in a questionnaire only when it is Active. |
| Subject Type | What the questionnaire is about, for example an encounter or a device. You select it when you create the questionnaire, and you cannot change it later. |
| Organizations | The departments that the questionnaire is shared with. This field is optional. |
| Questions | The questions and the groups of questions in the form. |
| Version | The version number, shown as v1, v2, and so on. Care sets it, and it goes up each time the questions change. |

### Where a questionnaire belongs

A questionnaire that you create in facility settings belongs to that facility. Care shows a **Facility** badge next to its title.

Some questionnaires are shared across the whole Care instance; they do not show in the facility's list, and they cannot be changed from facility settings.

### Slug

The slug has 5 to 50 characters. It uses only letters, numbers, hyphens, and underscores, and it starts and ends with a letter or a number. When you type the title on the create page, Care fills in the slug for you.

Two questionnaires in the same facility cannot have the same slug, and Care ignores capital letters when it compares them. Other facilities can use the same slug.

### Subject Type

The subject type says what the questionnaire is about: Encounter, Referral, Location, Device, or Facility. Patient questionnaires exist only for the whole Care instance, so facility settings do not offer Patient.

The subject type also decides what the questionnaire can hold. Care offers a structured question type only when it fits the subject type: for example, Medication Request and Service Request questions exist only in Encounter questionnaires. Actions run only for Patient and Encounter questionnaires.

### Questions

Each question has an answer type: Group, Display, Boolean, Decimal, Integer, Date, Date Time, Time, String, Text, URL, Choice, Quantity, or Structured. A Group holds related questions together and must contain at least one question. A Display shows text or instructions and collects no answer.

A question can have these settings:

- **Required**: the form cannot be submitted without an answer to the question.
- **Repeatable**: the person can record more than one answer. Care does not offer this setting for Boolean, Display, and Structured questions.
- **Read only**: the question is shown, but it cannot be answered.

A Choice question takes its answers from custom options or from a [valueset](./valueset.mdx). A Quantity question takes its units from a valueset.

On the **Logic** tab of a question, you set when the question appears; with no rules, it is always shown. On the **Coding** tab, you link the question to a standard code, so that answers are comparable across facilities.

### Versions

Care keeps the earlier versions of a questionnaire. When a save changes the questions, Care keeps the previous questions as a past version and raises the version number. A save that changes only the title, slug, description, status, or departments keeps the version number.

Past versions are read-only: you cannot edit a past version, and staff cannot fill in a past version. Each response keeps the version that it was answered with. You open past versions from the **Versions** tab of the questionnaire.

### Status

| Status | Description |
| --- | --- |
| Active | The questionnaire is in use. Staff can select it when they fill in a questionnaire. |
| Draft | The questionnaire is in preparation. Staff cannot fill it in. The create form selects Draft unless you select another status; a clone or an import always starts as Draft. |
| Retired | The questionnaire is no longer in use. Staff cannot select it when they fill in a questionnaire. |

Note: The questionnaire screens have no action to delete a questionnaire. To take a questionnaire out of use, set its status to Retired. To use it again, set its status back to Active.

## Permissions

| Permission | Access |
| --- | --- |
| Can Create/Update Questionnaires | Create, change, clone, import, and share the facility's questionnaires. Care checks this permission in the facility's root organization (**Administration**); the same permission in another department is not enough. By default, the Facility Admin role holds it. |
| Can Read Questionnaires | See and open the facility's questionnaires, in the questionnaire list and when you choose a questionnaire to fill in. Care checks this permission in the root organization, in a department that the questionnaire is shared with, or in a department above one. By default, the Facility Admin, Administrator, Doctor, Nurse, Staff, Pharmacist, and Volunteer roles hold it. |
| Can View Facility Organizations | List the departments of the facility in the department picker when you share a questionnaire. Care checks this permission in any department of the facility; held in the root organization, it lets the picker list every department. By default, the Facility Admin, Administrator, Doctor, Nurse, Staff, and Volunteer roles hold it. |

A new questionnaire is not shared with any department. Until you share it, only people who hold Can Read Questionnaires in the root organization can see it. A person who holds the permission only in other departments sees it, in the questionnaire list and when they fill in a questionnaire, after it is shared with one of their departments.

Your deployment can also have custom roles with other sets of permissions.
