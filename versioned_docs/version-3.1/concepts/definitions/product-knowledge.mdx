# Product Knowledge

## Definition

**Product Knowledge** in Care describes a product that a facility stocks or uses: a medication, a nutritional product, or a consumable. It records what the product is, not how much of it the facility holds.

Each [product](../supply/product.mdx) that the facility stocks refers to one Product Knowledge, and each [inventory item](../supply/inventory-item.mdx) refers to a product. You describe a product once, and many products and stock records can refer back to that description.

You manage the facility's Product Knowledge in **Settings**, in the **Inventory** group, under **Product Knowledge**.

## Key Attributes

| Components | What it captures |
| --- | --- |
| Name | The name of the product. This field is required. |
| Slug | A short name that identifies the Product Knowledge in the facility, 5 to 50 characters long. Care fills it from the name, and you can change it. This field is required. |
| Product Type | The kind of product: Medication, Nutritional Product, or consumable. The default is Medication. |
| Category | The category that holds the Product Knowledge. See Categories below. This field is required. |
| Code | A code for the product, which you find with a search of product codes. This field is optional. |
| Base Unit | The unit that Care counts the product in: tablets, gram, milligram, microgram, milliliter, drop, international unit, or count. This field is required. |
| Status | Draft, Active, or Retired. The default is Active. See Status below. |
| HSN Code | A secondary identifier for the product. This field is optional. |
| Alternative Names | Other names for the product. Each name has a Name Type: Trade Name, Alias, Original Name, or Preferred. The Product Knowledge page lists them under **Names**. This section is optional. |
| Storage Guidelines | Notes on how to store the product. Each note has a duration: how long the product stays stable. This section is optional. |
| Product Definition | The Dosage Form of the product and its Intended Routes. The create form shows this section at first, and you can remove it. This section is optional. |

### Categories

The facility keeps its Product Knowledge in categories, and a category can hold subcategories. You add Product Knowledge only to a category that has no subcategories, and the **Category** field accepts only such a category.

In a category that already holds Product Knowledge, Care does not offer **Add Category**. If the facility has no suitable category, a person with the permission to add categories adds one first. See [Add or edit a definition category](../../flows/definitions/resource-category/manage-definition-categories.mdx).

### Where Care uses Product Knowledge

- When you create a [product](../supply/product.mdx), you select the Product Knowledge that it belongs to.
- An [inventory item](../supply/inventory-item.mdx) belongs to a product, and through that product to its Product Knowledge.
- A [supply request](../supply/supply-request.mdx) names the Product Knowledge that it asks for.
- A [medication request](../medications/medication-request.mdx) can name the Product Knowledge of the product that it requests, and a medication administration can name the Product Knowledge of the product given.

Some Product Knowledge is shared across the whole Care instance: pickers can offer it, but you cannot change it from facility settings.

### Status

| Status | Description |
| --- | --- |
| Draft | Care keeps the Product Knowledge, but pickers do not offer it. |
| Active | Pickers offer the Product Knowledge, for example when you create a product. |
| Retired | The facility no longer uses the Product Knowledge. Pickers do not offer it. |

Note: In **Settings**, a category shows only Active Product Knowledge until you change the **Status** filter.

Note: The **Delete** button does not remove Product Knowledge. It sets the status to Retired, and Care keeps the Product Knowledge. To use it again, edit it and set **Status** to **Active**.

### Favorites and recent items

Some Product Knowledge pickers, for example the one in the product form, have **Recent** and **Favorites** tabs.

- **Favorites:** select the star next to Product Knowledge to add it to your favorites. Select the star again to remove it.
- **Recent:** Care adds the Product Knowledge that you select, with the most recent first.

Each list keeps up to 50 items, unless your deployment sets another limit. When a list is full, Care drops the oldest item.

Your favorites and recent items are your own. Other people do not see them, and Care keeps them separately for each facility.

## Permissions

| Permission | Access |
| --- | --- |
| Can Create Product Knowledge on Facility | Create, update, and retire the facility's Product Knowledge. Care checks this permission in the facility's root organization (**Administration**). By default, the Facility Admin role holds this permission. |
| Can Read Product Knowledge | See the facility's Product Knowledge in Settings. Care checks this permission in any department of the facility. By default, the Facility Admin, Administrator, Staff, Doctor, Nurse, Volunteer, and Pharmacist roles hold this permission. |
| Can Read Resource Category | See the Product Knowledge categories, and select one in the **Category** field. Care checks this permission in any department of the facility. By default, the Facility Admin, Administrator, Staff, Doctor, Nurse, Volunteer, and Pharmacist roles hold this permission. |

Care counts only the roles that you hold in the facility's departments. If you hold the create permission only in a department other than the root organization, Care does not save your changes.
